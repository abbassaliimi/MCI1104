Topic 02 Estimated Time: 10 Mins

The Prescriptive Framework: Two Core Pillars

To operationalize prescriptive analytics in real-world scenarios, organizations rely on two distinct mathematical paradigms depending on whether decisions govern resource allocations or personalized choices.

Pillar 1: Mathematical Optimization

Finding the absolute best mathematical solution under strict operational, resource, and budget constraints (e.g., Linear & Integer Programming).

Pillar 2: Recommendation Systems

Guiding human choices by predicting individual preferences using historical interaction patterns and feature matrices (e.g., Content-Based & Collaborative Filtering).

Comparing Prescriptive Architectures

1. Mathematical Optimization Hard Constraints

Solves precise resource allocation, supply chain routing, and cost minimization by maximizing or minimizing explicit objective functions.

Industry Example

Logistics Routing: Calculating exact delivery routes for 500 trucks to minimize fuel expenditure while satisfying hard time windows and vehicle weight limits.

2. Recommendation Engines Preference Ranking

Recommends tailored actions or products to individual users by scoring high-dimensional interaction behavior and item similarity vectors.

Industry Example

Personalized Commerce: Recommending top-3 movies on Netflix or products on Amazon by scoring user viewing patterns against peer preference matrices.

Topic 03A PILLAR 1: OPTIMIZATION

Linear Programming (LP)

Simple Definition: Linear Programming finds the best outcome when variables can take fractional numbers (such as 4.5 units or 8.2 hours). All goals and limits are straight-line equations.

Anatomy of an LP Model Continuous Variables
  • 1. Variables ($x_1, x_2$): Continuous units ($x_1 = 4.5$ units of Product A, $x_2 = 8.2$ units of Product B).
  • 2. Objective Function: Goal to maximize profit:
    $$\text{Maximize Profit } Z = 45 x_1 + 50 x_2$$
  • 3. Limits (Constraints): Resource limits (e.g., labor capacity):
    $$3 x_1 + 4 x_2 \le 100 \text{ hours}$$
Real-World LP Example

Liquid Batch Production: Manufacturing chemical batches where fractional outputs ($x_1 = 4.5$ thousand liters of Product A, $x_2 = 8.2$ thousand liters of Product B) yield a maximum profit of $Z = \$612.50$ within labor constraints).

LP Feasible Region Graph

Continuous Solutions

Key Takeaway: In Linear Programming, optimal solutions always land on a corner point of the shaded feasible area, allowing for exact fractional values ($x_1 = 4.5$, $x_2 = 8.2$).

Topic 03B PILLAR 1: OPTIMIZATION

Integer Programming (IP)

Simple Definition: Integer Programming is used when variables must be whole numbers (0, 1, 2, 3...) or binary Yes/No choices (0 or 1). Fractional answers are strictly invalid.

Anatomy of an IP Model Whole Numbers Only
  • 1. Variables ($x_1, x_2$): $x_1 = \text{Trucks}$, $x_2 = \text{Cargo Planes}$ ($x_1, x_2 \in \{0, 1, 2, \dots\}$).
  • 2. Objective Function: Maximize fleet profit:
    $$\text{Maximize } Z = 45 x_1 + 50 x_2$$
  • 3. Integer Solution: Optimal choice ($x_1=4, x_2=8$):
    $$Z^* = 45(4) + 50(8) = \$580$$
Real-World Fleet Example

Fleet Dispatching: Deciding how many Trucks ($x_1$) and Planes ($x_2$) to deploy. Sending 4 trucks and 8 planes ($Z = \$580$) is valid, but sending 4.3 trucks or 7.8 planes is physically impossible!

IP Grid Point Graph

Whole Number Constraints

Key Takeaway: Integer Programming restricts solutions to whole-number grid points (blue dots). Deploying 4 Trucks ($x_1$) and 8 Planes ($x_2$) yields the highest feasible profit of $\$580$.

Topic 04A PILLAR 2: RECOMMENDATION

Content-Based Filtering

Simple Definition: Content-Based Filtering recommends new items by matching their features and traits (such as genre, author, or product tags) to items a user already liked in the past.

How Content-Based Recommendation Works Item Traits
  • 1. Item Profile: Tagging products with attributes (e.g., Movie = Action, Sci-Fi, Director: Nolan).
  • 2. User Profile: Building a preference score based on tags of items the user interacted with.
  • 3. Similarity Matching: Recommending unrated items that have high feature similarity to past choices.
Real-World Content Example

Movie Streaming: If you watch Inception, the system extracts tags (Sci-Fi, Thriller, Christopher Nolan) and immediately prescribes Interstellar because its content features match your taste profile.

Item Feature Matching Flow

Attribute Driven

Main Advantage & Limitation: Requires no user community data to get started, but can lead to "filter bubbles" by only recommending items very similar to past choices.

Topic 04B PILLAR 2: RECOMMENDATION

Collaborative Filtering & Cold Start

Simple Definition: Collaborative Filtering ignores item tags and instead looks at people's behavior. If User A and User B share similar rating habits, items liked by User B are prescribed to User A.

User Behavior & Limits Peer Ratings
  • 1. Peer Behavior: Finds "taste twins" based on rating histories across the entire catalog.
  • 2. Cold Start Problem: When a user or product is brand new, there are no rating records available, so recommendations temporarily break down.
Real-World Collaborative Example

E-Commerce: "Customers who bought this item also bought..." Amazon prescribes products based on thousands of shared purchasing patterns across shoppers.

Key Takeaway: Collaborative filtering finds unexpected items you might love based on community taste, but requires historical rating data to work effectively.
